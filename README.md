# OrderPulse

A small, local e-commerce operations dashboard built with React/TypeScript, Express/TypeScript, and Python/FastAPI.
It contains 30 fictional orders, interactive status updates, and analytics calculated by a separate Python service.
The npm workspaces and pinned Python requirements are ready for separate dependency review.
The application includes no database, authentication, Docker, CI, or payment processing.

**Manifest-only CVE demo:** `demo/backend-known-cves` intentionally declares vulnerable backend dependencies.
Do not install its dependency snapshots or execute its application, build, or dependency-based test commands.
The original application baseline is preserved on `main` at `f5136bd`.

## Review boundary

Source and dependency manifests have been prepared without installing application dependencies, executing their lifecycle scripts, or starting the application.
The npm lockfile was generated by npm with `--package-lock-only --ignore-scripts --no-audit --no-fund --strict-peer-deps`.
Python pins were generated from a pip wheels-only dry-run report, which downloads metadata and wheels but does not install, import, or build them.
Registry resolution establishes published versions and dependency compatibility; it is not a security assessment.
Review the manifests separately before approving installation and execution.
Never install or execute a dependency identified as malicious by Socket.

The Python requirements include the full resolution for CPython 3.13 on macOS arm64, with plain Uvicorn and no optional framework extras.
Other operating systems may require a separately reviewed resolution for platform-specific dependencies or wheels.

## Configuration

The application runs with safe local defaults; copying the two examples is optional.

```sh
cp apps/web/.env.example apps/web/.env
cp apps/api/.env.example apps/api/.env
```

| Service | Setting | Default |
| --- | --- | --- |
| Web | `VITE_API_URL` | `http://127.0.0.1:3001` |
| API | `HOST` | `127.0.0.1` |
| API | `PORT` | `3001` |
| API | `WEB_ORIGIN` | `http://127.0.0.1:5173` |
| API | `ANALYTICS_URL` | `http://127.0.0.1:8000` |
| Analytics | `UVICORN_HOST` | `127.0.0.1` |
| Analytics | `UVICORN_PORT` | `8000` |

Vite loads its workspace `.env`; the API uses Node's native environment-file support.
Analytics uses Uvicorn environment variables or command-line flags, without an environment-file loader.
For example, changing the analytics port requires updating both `UVICORN_PORT` and the API's `ANALYTICS_URL`.
The API's allowed origin must match the frontend URL exactly, including `127.0.0.1` versus `localhost`.
Use the documented frontend URL so CORS succeeds.
Browser `VITE_` variables are public and must never contain secrets.
Environment files, virtual environments, build output, and caches are ignored.

```sh
cd services/analytics
UVICORN_HOST=127.0.0.1 UVICORN_PORT=8000 .venv/bin/python -m uvicorn app.main:app --reload
```

In terminal 2, from the project directory:

```sh
npm run dev:api
```

In terminal 3, from the project directory:

```sh
npm run dev:web
```

Open <http://127.0.0.1:5173>.
Health endpoints are <http://127.0.0.1:3001/health> and <http://127.0.0.1:8000/health>.
The Vite server requires port 5173 rather than silently changing ports and breaking CORS.
The API keeps all orders in memory; restarting it restores the original demo data.
If analytics stops, orders remain browsable and editable while metrics show an unavailable state and retry action.

## Demo walkthrough

1. Review the four overview metrics, revenue chart, and status breakdown.
2. Open the orders section, search a customer or an `OP-` order ID, and filter by status.
3. Open an order, review its line items, and save a different status.
4. Observe refreshed global metrics and the changed table entry.
5. Stop analytics to demonstrate partial service failure, then restart it and retry metrics.

All customers and products are synthetic.
Order dates are fixed from September 25 through October 8, 2026, rather than depending on the current clock.
Statuses are `pending`, `processing`, `shipped`, `delivered`, and `cancelled`.
All five are valid status-update targets; this demo has no fulfillment state machine.
Money is integer USD cents and daily buckets use UTC.
Revenue and AOV include processing, shipped, and delivered orders only; pending and cancelled orders still count toward total orders and the status breakdown.
AOV is rounded half up to the nearest cent, or zero when no orders qualify.
Daily revenue includes every represented UTC date, including dates with zero eligible revenue.
Search and status filters affect the table; overview analytics always cover the complete dataset.

## HTTP contracts

The browser calls Express; Express posts the complete current order snapshot to Python with a three-second deadline.
The API validates the returned summary before exposing it.

| Service | Route | Response or behavior |
| --- | --- | --- |
| API | `GET /health` | `{ "status": "ok", "service": "api" }` |
| API | `GET /orders?search=&status=` | `{ "orders": [...] }`, newest first |
| API | `GET /orders/:id` | `{ "order": {...} }` |
| API | `PATCH /orders/:id` | Accepts only `{ "status": "processing" }`; returns `{ "order": {...} }` |
| API | `GET /analytics/summary` | Summary object below, covering all orders |
| Analytics | `GET /health` | `{ "status": "ok", "service": "analytics" }` |
| Analytics | `POST /analyze` | Accepts `{ "orders": [...] }`; returns the same summary shape |

An order has `id`, `customer: {name, email}`, `createdAt`, `status`, `items: [{name, quantity, unitPriceCents}]`, and `totalCents`.
The summary has `totalRevenueCents`, `averageOrderValueCents`, `totalOrders`, `ordersByStatus` with all five status keys, and `revenueByDay: [{date, revenueCents}]`.
API errors use `{ "error": { "code": "...", "message": "..." } }`.
Invalid API requests return 400, missing orders return 404, oversized JSON returns 413, and analytics timeout, upstream failure, or invalid summary returns 503.
FastAPI rejects invalid analytics payloads with its standard 422 validation response.
No cached or invented summary is substituted when Python is unavailable.

Only regenerate after approving the intended dependency changes.
Use npm's metadata-only resolution from the project directory:

```sh
npm install --package-lock-only --ignore-scripts --no-audit --no-fund --strict-peer-deps
```

For Python, use the existing pip resolver with exact direct versions from `requirements.txt`, `--dry-run --ignore-installed --only-binary=:all: --report`, and place its report in a scratch directory outside this repository.
Generate the sorted `name==version` requirements from the report's resolved metadata.
Do not use source distributions, bypass TLS verification, invent hashes, or hand-edit npm lock metadata.
